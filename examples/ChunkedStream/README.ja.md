# ChunkedStream

> English: [README.md](README.md)

HTTP応答を分割送信して完了させるサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [ChunkedStream.ino](ChunkedStream.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<WiFi.h>`, `<EspHttpServer.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `server.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `server.on(...)` — PathとHTTP Methodを登録します。Handlerのオブジェクトは要求の寿命内で扱います。
3. `res.beginChunked(...)` — Chunk送信の前に分割応答を開始します。
4. `res.endChunked(...)` — Clientが終端を判断できるよう応答を完了します。

この例のルート: `GET /stream`

## APIの使い方と注意点

ローカルのWi-Fi設定を用意し、IP取得後に、基板へ到達できる端末から表示URLを開きます。ルートのパスとHTTPメソッドを合わせます。ハンドラはArduino loopではなくesp_http_server側で動くので、Request／Responseへの参照や捕捉したローカル値を要求の寿命内で扱い、長い処理で他の要求を止めないようにします。

パス・Query・Form・Multipart・Cookieは利用者からの入力です。二重波括弧は文字をescapeし、三重は生の出力を挿入します。信頼できない値を生HTMLやscriptデータへ入れる前に適切に処理します。

Cookieだけで認証済み利用者とは判断できません。SessionやLogin例は仕組みの説明で、例の認証情報や平文HTTPを含めて配備用認証を完成させるものではありません。Chunked応答は完了させ、組み込む際は開始／送信の結果も確認します。

beginChunkedで始め、各Chunkを送り、データが小さくてもendChunkedで完了します。同じ要求へ別の通常応答を重ねて送らないようにします。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

## 確認と問題の切り分け

HTTP応答を分割送信して完了させることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
